## Time Tracking

- `time-tracking/timesheet` **Timesheet** — Daily, weekly, bi-weekly, semi-monthly, or monthly timesheet (**Timesheet period** in **Timesheet and Planning Settings**) for logging time against projects, tasks, and time off, shown as a grid or a calendar; the **Categories** tab picks which project categories and plannings it offers (**Record time on these project categories**, **Record time on these plannings**); calendar entries on a task show how much of its planned time is logged, a dot flags time logged outside a task's planned dates, and people allowed to manage tasks can mark a task done from its row (**Set as done**)
- `time-tracking/calendar-view` **Timesheet calendar view** — Day-by-hour calendar alongside the timesheet grid: drag and resize entries to set start and end times directly (the duration shows while you drag, and holding ⌘ while dragging an edge snaps to whole hours), duplicate an entry by holding ⌘ while dragging it, drag a pinned favorite onto the calendar to log it (a plain click on a favorite no longer adds an entry), add an entry from the **+** button on each day's header even when the day is already full, zoom into a single hour (**Open this hour**) to work on a five-minute grid where very short entries are easy to read, drag and resize, click an empty slot to insert an entry pre-filled with the time still missing from the day's schedule, drop an untimed entry at the clock time you release it, and delete from a hover button; short entries that follow each other closely sit side by side instead of hiding one another; the calendar shares the grid's day headers, schedule totals, and progress bars, is the default timesheet view, and hovering an entry on today's calendar reveals a play/pause button that starts or pauses a timer on it, with the duration ticking up live in place
- `time-tracking/timer` **Timer** — Start/stop timer for real-time tracking, started from the timesheet, from a calendar entry, from a pinned favorite chip, or from a suggestion (in start/end mode the play button on a suggestion simply starts and stops the timer on that task or project, the draft shrinking as tracked time covers it); several timers can run at once — ⌘/Ctrl-click any play button to start a timer without stopping the others — and the floating timer is a shelf with one line per activity, each showing the project it belongs to (parent projects as short initials, the full path on hover), a live counter for running ones, a play button to resume paused ones, and a pause-all action; the browser tab title shows the elapsed time, or the number of timers when more than one is running; **Enable timer** in **Timesheet and Planning Settings** turns the timer on or off, its **Mandatory** option makes it the only way to enter time, and timed durations are rounded up to the minimum time interval
- `time-tracking/entry-modes` **Time entry modes** — **Unit for time entry** sets whether people enter **Hours**, a **Day or fraction of day**, or a **% of schedule** (share of the person's scheduled day); with hours, the **Duration format** (3:15, 3.25, or 3h15) and the **Minimum time interval accepted** apply, and durations and calendar drags snap to that interval
- `time-tracking/duration-or-start-end` **Duration or start/end** — Enter time as a duration or with start and end times; **Record start and end times** in **Timesheet and Planning Settings** turns clock times on, and its **Mandatory** option requires them on every entry
- `time-tracking/wfh-flag` **Work from home (WFH) flag** — Mark entries as remote work
- `time-tracking/non-billable-flag` **Non-billable flag** — Mark specific entries as non-billable; the **Hide the non-billable option** timesheet setting removes the checkbox from the entry form, so records can no longer be marked non-billable and cloned entries lose the flag
- `time-tracking/row-pinning` **Row pinning** — Pin frequently used project/task combinations for quick access
- `time-tracking/comments` **Comments on time entries** — Add notes to individual time records
- `time-tracking/copy-paste` **Copy/paste time entries** — Duplicate entries across days or weeks
- `time-tracking/clear-rows` **Clear rows per section** — Hover-to-reveal button that clears one section's rows and its time entries for the current period (undoable); replaces the old all-or-nothing "Clear timesheet" action
- `time-tracking/auto-submit` **Auto-submit** — **Auto-submit timesheets after X days** closes each period that many days after it ends: the remaining suggestions become entries and the timesheet is submitted into the approval workflow, or, for people without an approval workflow, approved and closed directly (the only way their periods close); only the single period whose deadline has just passed is processed, empty or partly locked periods are skipped, a rejected timesheet is never resubmitted automatically, and a period that can't be processed stays a draft marked **Auto-submit failed** in the Team pane while admins are notified
- `time-tracking/auto-timesheet` **Auto Timesheet from Planning** — Optional setting (**Enable Auto Timesheet from planning** in **Timesheet and Planning Settings**) that turns task-status moves into time suggestions: for each chosen planning you pick a **Start** and an **End** status, and when a task moves into the start status and later into the end status, the time between is proposed on the task owner's timesheet (the person who moved it becomes owner when the task has none); moves always suggest rather than writing entries directly, and planned work reaches the timesheet through the Planned suggestions whether or not this setting is on
- `time-tracking/duplicate-and-start` **Duplicate and start** — Duplicate a time entry and start a new one based on it
- `time-tracking/reminders` **Timesheet reminders** — **Remind to submit** at the **End of current period** or the **Start of next period**, at a chosen hour (Reminders tab of **Timesheet and Planning Settings**, organization-wide or per tag or person); the email lists what is logged so far, how many suggested entries are waiting, and when auto-submit will act, with a **Submit now** link; reminders go only to people with an approval workflow whose timesheet is still a draft or was rejected (never for daily timesheets), and managers can also send one from the Team pane
- `time-tracking/entry-restrictions` **Time entry restrictions** — Rules added from the **Add restriction** menu in **Timesheet and Planning Settings** (organization-wide, or per tag or person) and shown as removable chips: **No overtime beyond the schedule** (daily and/or period), **Require filling the whole schedule to submit** (daily and/or period), **Require comments for submission**, **Only time off can be recorded in the future**, **Only allow time entries on scheduled working time** (blocks days off and public holidays), **Keep start/end times within the scheduled hours** (as a warning or a block), **An absence can't be longer than a day**, **Hide the non-billable option**, **Only the owner or an admin can edit entries** (which absorbed the former "Only an admin can edit someone else's timesheet"), and **Allow only planned tasks in the timesheet** (the tasks planned for the person, from every planning, appear in their timesheet on their own, time can be entered only within each task's planned dates, no other row can be added, task pickers, favorites and suggestions offer only the person's own tasks, copy/paste is off, time off stays available, and project categories only serve to log a booking's time on its project); a **DCAA compliance** choice turns on owner-or-admin editing and no future time except time off in one step, after which each shows as its own chip that can be removed separately (one undo reverts both); when time entry is limited to owned tasks, task pickers offer only those tasks; independently of these chips, entries always stay within project and person validity dates and, unless the allowance allows a negative balance, within the time-off balance; deleting several entries at once validates every entry first, so a locked or invalid one stops the whole deletion rather than leaving a partial result
- `time-tracking/lock-date` **Lock date** — Freeze all time records on or before a chosen day — no creating, editing, moving, or deleting for anyone, admins included — and a period whose last day falls on or before the lock date can no longer be submitted for approval, while auto-submit skips any period that is even partly locked; set organization-wide or per tag or person (**Lock date** in **Timesheet and Planning Settings**), and applied everywhere including the BambooHR time-off sync and connected AI assistants
- `time-tracking/record-locking` **Record locking by state and role** — Who may change a person's time entries follows the timesheet's approval status: in draft or after a rejection, the person, their managers (on the projects and tasks they manage), and admins; once submitted, the person is locked out and only the current stage's approvers — whose correction sends the timesheet back to the first approval stage — or an admin; once approved, only an admin; the **Only the owner or an admin can edit entries** restriction keeps managers and approvers out at every stage, and the lock date overrides everything, admins included
- `time-tracking/mobile` **Mobile timesheet** — Mobile-optimized layout for phones and small tablets, with infinite scroll, swipe-to-delete, and bottom-sheet editors for adding and editing entries; time suggestions appear as ghost rows inside each day next to real entries — accept one with a single tap, or open it to change the duration, start and end times, retarget it to another task or working activity, start a timer on it, or dismiss it; pickers list items alphabetically and leave out archived projects, tasks, and time-off types, and **Your activities** shows the most recent first without archived rows
- `time-tracking/score` **Timesheet score** — Per-person compliance score (0–100) tracking on-time submissions, late submissions, missed timesheets, and rejections, shown as a color-coded score per person in the Timesheet compliance report and available through the API; people without an approval workflow have no score, since they cannot submit; the ring gauge that used to circle each person's picture in the Team and Approval panes was removed in September 2026
- `time-tracking/custom-fields` **Custom fields on time entries** — Extend time records with organization-defined fields (text, number, date, boolean, etc.) for capturing additional context per entry
- `time-tracking/calendar-integration` **Calendar integration in timesheet** — Connect Google Calendar or Microsoft Outlook and drag calendar events onto timesheet rows to log time, with events shown alongside the timesheet for the displayed period

## Absence & Time-Off Management

- `absence/types` **Configurable absence types** — Time-off types (vacation, sick leave, parental leave, etc.) managed under **Settings > Time Off**; type pickers show only the types each person is allowed to use, including when a manager or admin books on someone's behalf (enforced on save too), and the **Allow recording time off** timesheet setting can take time off out of a timesheet altogether
- `absence/cost-tracking` **Absence cost inclusion** — Mark each absence type as paid or unpaid with the **Is paid (included in people costs)** checkbox (checked by default); paid absences are automatically included in people cost totals shown in reports (time off never carries a project, so it does not consume project budgets)
- `absence/accrual` **Accrual policies** — Configurable per time-off type: frequency (weekly, bi-weekly, twice-monthly, or monthly), quantity, and when within each period the credit is awarded. _(status: hidden-flag — the **Accruals** panel on time-off types is suppressed on production hosts (`isProduction()` in `services/entity/attributes.ts`, since 2026-06-23) and the automatic awarding engine is not implemented (feature request `7. absence-accrual-engine.md`); only the allowance's manual **Accrued** field is visible; do NOT document the policy settings. Re-verified 2026-10-08)_
- `absence/carry-forward` **Carry-forward rules** — When an allowance has a **Valid until** date past its period end, the unused balance stays usable until that date, capped by the **Carry forward limit** (0 means no cap) and spent before the next period's allowance; without a **Valid until** date nothing carries over; booking limits and the absence quota report reflect the carried balance
- `absence/negative-balance` **Negative balance controls** — The **Allow negative balance** checkbox on each allowance decides whether time off can go below zero; when it is off, a booking that would exceed the remaining balance (carried-forward time included) is refused
- `absence/quotas` **Absence quotas** — Time-off allowances (**Absence allowances**) defined for the whole organization, a tag, or a person, each with a **Start - end** period and an **Allowance** in the type's unit; a person uses the allowances of the most specific level that has any (person, then tags, then organization), allowances can be copied to other people or tags, and past allowances can be hidden
- `absence/balance-tracking` **Absence balance tracking** — Each allowance card shows its **Allowance** and manual **Accrued** adjustment and, on a person, the **Consumed** amount, accurate even when allowances overlap or carry forward; every quota field states its own unit (days or hours) in the input and in the card summary, so hour-based and day-based allowances cannot be confused; remaining, taken, planned, and pending amounts across people are in the Absence quota report
- `absence/unit-config` **Unit configuration** — Each time-off type is counted in hours or days (**Units**); day-based time off is booked as a **Full day** or **Half day** of the person's schedule and can't be booked on a public holiday or a scheduled day off
- `absence/approval` **Absence approval** — Time off is entered in the timesheet and approved with it, through the same approval workflow; there is no separate leave-request flow
- `absence/notifications` **Absence notifications** — Alerts for negative balances, advance bookings _(status: hidden-flag — the **Time off notifications** panel is suppressed on production hosts (`isProduction()` in `services/entity/attributes.ts`), and no backend code sends these alerts; do NOT document. Flagged 2026-10-04)_
- `absence/excess-occurrence-notifications` **Absence frequency alerts** — Send administrators an alert when a team member takes absence more than a configured number of times within a month or year, helping flag attendance patterns early _(status: hidden-flag — same **Time off notifications** panel, suppressed on production and never sent; do NOT document. Flagged 2026-10-04)_
- `absence/public-holidays` **Public holidays** — Automatically populated country-specific public holiday calendars assignable at organization, tag, or person level; load the calendar for a specific year (recent past years included) and keep custom edits when reloading the same country; the calendar's country and region can be changed at any time, re-deriving every year's holidays — past years included — from the new country
- `absence/custom-holidays` **Custom holidays** — Add your own holidays, or rename, move, or remove individual holidays of the loaded country calendar
- `absence/archive` **Archive/unarchive absence types** — Soft-delete absence types without losing historical data

## Approval Workflows

> Covers approval of both time entries and absences.

- `approval/multi-stage` **Multi-stage approval** — Sequential approval stages (e.g., people manager → project manager → admin) set in the **Approval workflow** for the organization, a tag, or a person; new organizations start with a single **Admins** stage, a stage with nobody to approve is skipped, and a timesheet whose stages have no approver at all is approved on submit
- `approval/types-per-stage` **Approval types per stage** — Approvers can be: admins, project managers, people managers, task managers, tagged people, or specific named people
- `approval/quorum` **Quorum settings** — Require all approvers or any single approver per stage
- `approval/submit` **Submit for approval** — People send a finished period for review with **Submit** (**Resubmit** after a rejection) from the timesheet, the mobile app, or a reminder email's **Submit now** link; the button appears only when an approval workflow applies to the person — without one nobody can submit and periods close only through **Auto-submit timesheets after X days** — and submitting enforces the submission rules (required comments, required schedule, no overtime) and refuses a period ending on or before the lock date
- `approval/actions` **Approve / Reject** — Approvers **Approve** or **Reject** a submitted timesheet; a rejection needs a reason — an empty comment is refused — which is posted to the person's journal so they always see why it came back, and the person corrects it and uses **Resubmit**; an admin or a last-stage approver can also reject an already approved timesheet to reopen it; the only other interventions are the admin force actions below
- `approval/history` **Approval history & audit trail** — Full log of approval actions with timestamps
- `approval/change-tracking` **Change tracking** — Entries added, changed, or deleted after a rejection are tracked: on resubmission, earlier project-manager and task-manager stages only ask the managers of the changed projects or tasks to approve again (nobody, when nothing changed), and every change shows in the timesheet's journal as an old → new trail
- `approval/force-edit` **Force-edit a team member's timesheet** — Admins, managers, and approvers can open and edit a team member's timesheet directly from the Approval and Team panes without rejecting it, via a per-person **Edit timesheet** toggle tied to the person you chose; the whole editing area — grid, calendar, and pickers — carries a consistent highlight tint while you are in override mode; what you may change follows record locking: managers correct draft and rejected timesheets (on the projects and tasks they manage), the current stage's approvers correct a submitted one (which restarts the approval chain), only admins change an approved one, and with **Only the owner or an admin can edit entries** on, only admins can
- `approval/force-approve-reject` **Admin force-approve and force-reject** — Admins can approve or reject any submitted timesheet even when they are not a designated approver for the current stage; their approval completes that stage regardless of its quorum (later stages still need their own approval)
- `approval/team-overview` **Team approval overview** — The **Pending** tab lists the timesheets waiting for your approval (**Show all** widens it to every pending timesheet you can see) and the **Team** tab shows each team member's status for the period; select several people to approve, reject, or remind them in bulk — each bulk action acts only on the people it applies to (only people with an approval workflow and a draft or rejected timesheet are reminded; locked people never are) and strictly on the period on screen; the Journal also opens with a banner counting the timesheets waiting for your approval (**All caught up** when there are none), which expands into each person's pending timesheet with hours, billing, and cost when you may see it, late ones first under **Late**, with a per-project split, **View records**, and approve or reject for several at once
- `approval/email-actions` **Email actions** — Act on a timesheet from email notifications: the **Approve** button approves it and lands you on the timesheet it acted on, while **Reject** opens the timesheet's rejection dialog, since a rejection needs a reason; you can also reply to the approval email with "approve", or "reject" followed by a reason — Beebole verifies the reply came from you, applies the decision, and emails back a confirmation
- `approval/reminders` **Approval reminders** — **Remind approvers after X days if not yet approved** (Reminders tab of **Timesheet and Planning Settings**, organization-wide or per tag or person): approvers who haven't acted are reminded after that many days, then again at growing intervals while the timesheet stays pending; each reminder carries the timesheet summary and one-click approve/reject links
- `approval/email-summary` **Timesheet summary in emails** — Approval requests and approval reminders include a summary of the submitted time with the full project and task paths, each approver's copy listing only the projects and tasks they can access; timesheet reminder emails carry the same summary of what is logged so far
- `approval/mobile` **Mobile approval** — Mobile-optimized approval flow for reviewing and acting on pending timesheets from a phone or small tablet

## Planning, Tasks & Staffing

> The app's sidebar labels this area **Planning**, and task categories are called **plannings** in the UI (e.g. "Add a planning"). Individual items are still called tasks.

- `tasks/add` **Add task** — Create a task in the current planning with **Add Task**, with the **+** of a Kanban column (the task starts in that column's status), or several at once by pasting rows copied from a spreadsheet into the add form (**Or add multiple entries**, one entry per line, Tab or spaces to indent sub-levels); in the Gantt and the task list view, the **+** on a row (or on a group header) names a new subtask (or a task at the top of the group, carrying the group's owner, status, or project) right in place: Enter saves it and opens the next one, pasting several lines (one per line with indentation for nesting, or one line separated by semicolons) creates them all at once, leaving the field saves what was typed, Escape or the ✕ closes it, and ⌘-click on the **+** opens the full add form instead; in a Bookings planning every **+** opens the add-booking form (see `tasks/staffing-bookings`)
- `tasks/planning-mode` **Planning mode: Tasks or Bookings** — Each planning holds either **Tasks** (a to-do list, issues, tickets: items with a name and a status) or **Bookings** (who is on which project, a vacant position, someone expected present), chosen under **What this planning holds** in the planning's settings; the mode decides what the add button opens (**Add Task** or **Add Booking**) and whether items carry their own name, while Gantt, Kanban, List and Staffing stay available on every planning; switching keeps every stored name — a booking shows its project and person instead, and its own name comes back if the planning returns to Tasks; a new planning opens in the mode last picked (Bookings by default); in a Tasks planning, dragging on the Staffing timeline opens the add form with the dates and person already filled in, and the **+** on a Gantt or List row or group header names the new task in place, while in a Bookings planning every **+** opens the add-booking form with the row's parent task, project, owner, or status already filled in
- `tasks/kanban` **Kanban board view** — Cards in one column per status: drag cards between and within columns (several at once after a ⌘/Ctrl-click or Shift-click selection), add a task or booking straight into a column with its **+**, choose which details cards show (**Show**: Parent, Owner, Assignee, Dates, Projects, Tags), and use each column's menu to mark its cards **Done** or **Reopen** them (all of them, or only the selected ones), push them to the neighbouring column (**Move entries to left** / **Move entries to right**), or **Delete** an empty status; each card shows the time already tracked on it (against Planned when set) and an **Add time** button that logs time for today
- `tasks/kanban-wip-limits` **Kanban WIP limits** — Set a maximum number of concurrent tasks per status column on the Kanban board
- `tasks/gantt` **Gantt chart view** — Timeline visualization of tasks with start/end dates, dependency links, and configurable time precision; the timeline scrolls into the past as well as forward, can be pinned to a fixed window of 1, 2, 3, 4, or 6 weeks and paged one period at a time, and clicking a timeline header cell zooms one level into that period; month boundaries are marked with a line and a label; task cells — Planned, occupation, status, owner, dates, projects, tags, potential owners — are editable in place, the **+** on a row names a subtask in place (see `tasks/add`), ⌘/Ctrl-click or Shift-click selects rows and ranges for mass edits applied as one undo step, and an arrow next to an off-screen task's dates jumps to its bar — locating a task from anywhere moves the timeline onto the period holding it and scrolls smoothly, even when the task lies outside the period currently shown; planned figures can switch between hours and days, converted with each person's own working calendar rather than a fixed 8-hour day, and hours on bars and in tooltips follow the organisation's duration format; the **Potential owners** column has separate add-person and add-tag buttons, and a person, tag, or project can be removed straight from the row by hovering its badge and clicking the X
- `tasks/gantt-columns` **Gantt and list columns** — Choose the columns of a Gantt or List view from **Columns** in the view menu or a header's menu (**Show column** / **Hide column**): **Dependencies**, **Dates**, **Owner**, **Potential owners**, **Planned**, **Occupation**, **Status**, **Tags**, and one column per project category, always after **Row #** and **Task Name**; drag headers to reorder, drag edges to resize, and click a header to sort (**Sort ascending**, **Sort descending**, **Manual order**), with sorting and grouping working together
- `tasks/gantt-grouping` **Gantt and list row grouping** — Group Gantt and List rows (**Group by**) by **Owner**, **Status**, any level of a project category, or any level of a tag category, with **Show all groups** to keep empty groups visible; each group header's **+** names a new task at the top of the group, already carrying the group's owner, status, or project
- `tasks/gantt-keyboard` **Task view keyboard navigation** — Arrow keys move a cursor through tasks in every task view (Gantt, List, Kanban, Staffing), Enter opens or closes the task panel (which follows the cursor), Shift or ⌘ with an arrow extends a multi-selection, and in the tree views Right/Left expand and collapse while Tab/Shift-Tab indent and outdent the task; ⌘+A opens the add form for a subtask of the task shown in the panel (or for a new task), and Delete or Backspace deletes the selected tasks
- `tasks/gantt-workload-heatmap` **Gantt workload heatmap** — Color-coded bars on Gantt group rows show each group's effort against available capacity per day or week, with a per-person breakdown on hover and a workload indicator under each date in the timeline header
- `tasks/list` **Task list view** — Sortable, spreadsheet-like table of tasks sharing the Gantt's rows, columns, grouping, and expansion: click a header to sort (row numbers return to the manual order), drag to reorder and resize columns, pin columns so they stay on the left while you scroll sideways (the pin next to each column in **Columns**; dropping a column into or out of the pinned block pins or unpins it, and **Row #** and **Task Name** always stay on the left), edit owner, status, dates, Planned, occupation, potential owners, tags, and each project category in place, add subtasks with the **+** on a row, mark a task **Done** (or **Reopen** it) and delete it with the buttons at the end of its row, and select several rows with ⌘/Ctrl-click or Shift-click to apply one change to all of them as a single undo step
- `tasks/staffing` **Staffing view** — Long-horizon timeline of who works on what and when, alongside Gantt and Kanban: rows by people or by a project category (**Staffing by**: its **Lowest level** or any named level), drag on the timeline to create a booking, move or resize it, open its editor to change the person, project, and allocation (see `tasks/staffing-bookings`), narrow the rows with filters (see `tasks/tag-filter`), and show each row's tags for chosen tag categories (**Show tags**); bars can be linked with the same dependencies as the Gantt (linked bookings follow the planning's **Dependent tasks** setting), and an Unassigned row holds planned work nobody has picked up yet (counting only the bookings visible in the period) and can be pinned under the header so its bars stay in reach while scrolling; dragging a bar sideways keeps its exact length and starting weekday (whole weeks at week precision); the timeline can be pinned to a fixed window of 1, 2, 3, 4, or 6 weeks and paged one period at a time, bookings for tasks with hours are drawn at their real position inside the day column with non-working stretches hatched behind them, a part-day booking dragged within its day follows the pointer on that day's clock (snapping to the quarter hour and stepping over breaks) and moves by whole days once the pointer leaves the cell, ⌘-dragging a copy inside the same cell drops it right after its source, several bookings can be selected and deleted in one undoable batch, and **Copy the previous period** (**With people** or **Without people**; with or without projects when staffing by project) looks back to the last period that actually has bookings and fills every empty period in between; hours on bars and in tooltips follow the organisation's duration format; the today line is drawn per row so it stays visible behind pinned rows and stuck group headers, a booking created on the Unassigned row saves nothing until the person or task is picked (an abandoned editor leaves no stray booking), and a project row above the lowest level stands out in the accent colour with a note explaining that its bookings should be moved down
- `tasks/staffing-bookings` **Bookings** — Book a person on a project for a period without naming a task: the booking is named after its project and person across Staffing, Gantt, List, and Kanban (in a Bookings planning it cannot be renamed). **Add Booking** opens a form with a project, a person (one of the two is enough; a booking with no person is a vacant position on the Unassigned row), a date range, and the planned time, filled in from the person's working schedule for that range at the chosen allocation and editable (as a duration in the organisation's format, or in days when the view plans in days); the period you last used is remembered (a start date in the past falls back to today), a booking added from a Kanban column is created in that column, and one added with the **+** of a task row lands under that task. The booking editor sets the person, the project, and the allocation as a share of capacity (**%**), time per working day (**h/day**), or **Total** planned time, the last two entered as durations in the organisation's format, with your last choice of unit remembered; changing the person or project moves the booking to its new row in one step and the view follows it there; a booking can be marked **Tentative** (it reserves the person's capacity but stays out of reports until confirmed), duplicated, split in two on a chosen date (**Split** / **Split on**), or deleted
- `tasks/staffing-capacity` **Workload & capacity** — Each person's workload and remaining capacity at a glance in the Staffing view, absence-aware, with an overload indicator in the timeline header (click it to step through the overbooked bookings or the people with time left) and planned headcount (FTE and people) per period when staffing by project; **Find capacity** narrows the people rows to those matching an availability over a chosen period (**Has free time**, **Free at least** a given time, **Nothing planned**, or **Overbooked**)
- `tasks/views` **Saved task views** — Create (**Add a view**), rename, duplicate, delete, and switch between your own named views of a planning, each with its own layout (**Gantt chart**, **Kanban**, **Staffing**, or **List**), columns, grouping, sort, filters, period, and planned unit (**Durations in** hours or days); new accounts start with ready-made Staffing, Kanban, and Gantt views rather than an empty task screen
- `tasks/tag-filter` **Planning filters** — **Add filter** on any task view to narrow it by **Task**, **Status**, **Owner**, **Owner tag**, **Potential owner**, **Potential owner tag**, **Project**, **Task tag**, or **Project tag** (Status is left out on Kanban, where statuses are the columns), plus **Person tag** and **Person custom field** in Staffing to narrow the people pool; filters are saved with the view and can be switched off and back on (**Disable filters** / **Enable filters**)
- `tasks/hours` **Task start and end times** — Give a task exact hours, not just dates: uncheck **All day** in the task period editor to set start and end times, pre-filled from the owner's own working hours. Dragging, resizing, splitting, and copying keep the hours; typing Planned hours reflows the task to the exact minute the owner's calendar can hold, skipping breaks, days off, and absences; times falling outside the owner's working hours are highlighted with the reason; and the capacity a timed task consumes is measured on the hours it actually spans
- `tasks/dependencies` **Task dependencies** — Link tasks as predecessors and successors to define execution order: drag the handle on a task bar onto another task (hold ⌘ on the drop to chain several links), click the tasks that start after or end before it, or type row numbers in the **Dependencies** column; lines route around bars and group headers, and each planning chooses how linked tasks follow a moved or resized task (**Dependent tasks** in the view menu): **Free** leaves them in place, **Pushing** pushes them only when the moved task runs into them, **Together** moves the chain as a block, in both the Gantt and the Staffing view; rescheduled tasks are fitted to their owners' real working calendars, and a drag that the owner's calendar cannot absorb leaves the task in place and keeps its Planned hours intact
- `tasks/end-date-lock` **Lock start or end date** — A lock on each end of a task's dates (**Lock start date** / **Lock end date** in the task's period editor) decides which date holds when the period is refitted to the task's Planned time or Occupation: with the start locked (the default) the end date moves, with the end locked the deadline stays put and the start moves instead
- `tasks/effort-occupancy` **Planned time & occupation** — Give a task its **Planned** time (in hours or days) and an **Occupation** percentage of its owner's time; the task panel compares Planned with what the owner's working calendar holds between the task's dates (planned over available, with any overload shown) and offers one-click fixes — reduce Planned to what fits, or move the free end of the period (**Change end date to …**, or the start when the end is locked) — warns **Overlapping tasks causing overload** when the owner's other tasks in the same planning push them past capacity (each with **Show in the chart**), and **Plan on non-working days** lets a task count weekends and holidays as working days (absences stay non-working)
- `tasks/hierarchy` **Hierarchical tasks** — Tasks live in plannings (create as many as needed, **Name of a new planning**) and nest to any depth: add a subtask with the **+** on its parent's row, indent and outdent with Tab and Shift-Tab, drag rows to reorder them, or pick a new parent with **Change parent** in the task panel's breadcrumb (always within the same planning); a parent task's dates span its subtasks and its Planned time is their total, so dates and planned time are set on the lowest-level tasks, where time is also logged
- `tasks/statuses` **Task statuses** — Each planning has its own ordered list of statuses (**Task statuses** in the planning's settings, also reachable from the Kanban board): add one (**Add new status**), rename it, change its colour, drag to reorder, give it a **Max tasks** limit, or delete it once no task uses it (a planning keeps at least one); statuses are the Kanban columns and the status control in the task panel, new tasks take the first status unless added from a column, and marking a task done is separate from its status (see `tasks/archive`)
- `tasks/ownership` **Task ownership** — Give each task one **Owner**, whose working calendar drives its scheduling and capacity, and list its **Potential owners** — people, or tags whose members qualify — who may pick the task up while it has no owner (on a phone with **Take it**); both are set in the task panel or straight from the Gantt and List columns
- `tasks/managers` **Task managers** — Name the people who manage a task in its **Managed by** section (or let them manage a whole planning, or the tasks tagged with a tag they manage); managing a task covers its subtasks, and task managers can record time for others on the tasks they manage, approve in stages that use task managers, and receive unassigned-task warnings
- `tasks/projects` **Link tasks to projects** — Tasks stay independent of projects but can be linked to any number of them from the task's **Projects** section or the per-category project columns of the Gantt and List; project filters in reports include the time logged on linked tasks, a booking takes its project this way, and each project lists its linked tasks under **Tasks and bookings**
- `tasks/unassigned-warning` **Unassigned task warnings** — A configurable number of days before a task with no owner starts (**days before an unassigned task starts** in **Timesheet and Planning Settings**), its managers (including those of a parent task) and the people assigned to it are notified, or the admins when the task has no manager

- `ui/undo-redo` **Undo/redo** — ⌘+Z / ⌘+Shift+Z (Ctrl on Windows/Linux) or the undo and redo buttons, with bulk changes undone as one step; a deletion shows a toast with **Undo** that puts the item back where it was, and on phones a **Last action** bar offers **Undo** and **Redo**
- `ui/global-search` **Panel search** — Fuzzy search within each panel/list; there is no single cross-application search
- `ui/realtime-sync` **Real-time sync** — Changes by teammates appear instantly without refreshing
- `ui/offline-fallback` **Fallback-mode indicator** — When the network blocks real-time updates, the app keeps working over a slower connection and a sidebar icon (**Running in slower compatibility mode**) explains how IT can restore full speed; when no connection can be made at all, a **Can't establish a secure connection** screen suggests another network and offers **Try again**
- `ui/connection-diagnostics` **Connection diagnostics page** — A standalone **Connection Diagnostics** page (at `/diagnostics/`, which support shares when troubleshooting; it is not linked from the app) runs health checks, measures latency and inspects browser storage, lets you download or copy a snapshot for support, and clears the app cache or all site data before reloading
- `ui/fast-loading` **Fast loading** — Data is cached locally for near-instant page loads
- `ui/attribute-copy-paste` **Attribute copy/paste** — Copy billing, cost, budget, or quota configurations between entities
- `ui/duplication` **Entity duplication** — **Duplicate** in an item's menu creates a copy with its settings: people (asking for a new name and email), projects (with their sub-projects), tasks, tags (without the items they tag), roles, work schedules, time off types, expense types and custom fields; rates, budgets and staffing bookings have their own **Duplicate** button
- `ui/nl-conversation` **Plain-language sentence box** — One shared box behind every place you can ask for something in plain English (master data reviews and the report builders): tabs name what a sentence does there, each question and its answer stay on screen, and earlier turns are available behind "Whole conversation"
- `ui/tooltips` **Tooltips and in-app help** — Hover tooltips explain buttons and badges, and an info button on each section of a details panel (person, project, task, tag, settings) opens a short help text in your language
- `ui/toasts` **Toast notifications** — In-app success/error feedback
- `ui/color-coding` **Entity color coding** — Every person, project, task, tag, role, work schedule, time off type, expense type and custom field has a color, chosen from a palette on its picture, that tints its badge and initials; categories and task statuses have colors too
- `ui/profile-pictures` **Profile pictures** — Upload a picture for a person or any other item (projects, tasks, tags, roles, work schedules, time off and expense types, custom fields, the organization) and frame it with the crop tool; items without a picture show their initials on their color
- `ui/breadcrumbs` **Breadcrumb navigation** — Hierarchical entity paths: the details panel's breadcrumb starts with the item's category (for example the planning), which you click to open; project, task and tag badges spell out the full parent path whenever it fits the available space and cut a long parent path short with "…" when the label would be clipped, and badge tooltips always show the complete path; hovering a project or task name in a badge or the timesheet popup header shows its description
- `ui/attribute-deep-links` **Attribute deep links** — The URL follows the attribute you are reading as you scroll an entity's panel, so a shared link opens on the section that was on screen, the same section stays in view when you switch entity, and an attribute opened from a link stays at the top of the panel until you scroll or type
- `ui/version-updates` **Version update notifications** — Notifies you when a new version of the app is available and prompts a one-click reload; the prompt appears only when a new build really is live and can be dismissed with Escape instead of forcing an immediate reload
- `ui/support-chat` **In-app support chat** — Built-in support chat widget for reaching the Beebole team directly from the app
- `ui/onboarding` **Onboarding questionnaire** — When a new account is first opened, a short welcome questionnaire asks what you plan to use Beebole for, your role, team size, the tool you use today and how you heard about Beebole, offers to be contacted for a product demo, and ends on a screen confirming the 30-day free trial; the answers help Beebole follow up and change no settings (it serves Beebole's activation funnel rather than ongoing product use)
- `ui/release-notes` **In-app release notes** — Admins open **Release Notes** in the Settings menu to read what changed in each production release, newest first, ten at a time with **Load older**

## Internal (Non User-Facing)

> These capabilities exist in the codebase but are internal development and operations concerns. They are listed here for completeness so they are not re-flagged during future syncs.

- `internal/posthog` **PostHog analytics / eventing** — Product analytics and event tracking for internal metrics
- `internal/translation-engine` **Translation engine** — Internal script (`i18trans.ts`) for managing i18n JSON files (the resulting multilingual UI is user-facing and listed as `ui/multi-language`)
- `internal/migration-optimization` **Migration batch optimization** — Internal performance tuning for the legacy migration process
- `internal/notification-outbox` **Notification outbox & retry** — Reliable delivery architecture for notifications (the notifications themselves are user-facing)
- `internal/graphql-enhanced` **GraphQL-enhanced library** — Custom GraphQL execution engine used internally
- `internal/code-formatting` **Code formatting & linting** — Prettier, TypeScript strict mode, and code style rules
- `internal/websocket` **WebSocket event system** — Real-time communication layer between server and client (enables the live updates users see)
- `internal/jwt-cookies` **JWT & cookie management** — Authentication token handling and session management internals
- `internal/file-soft-delete` **File attachment soft-delete** — Deleted file and image attachments enter a grace-period queue (`scheduleFileDeletion` / `cancelFileDeletion`) before permanent removal; recovery is handled internally
- `internal/support-panel` **Support admin panel** — Internal tool for Beebole support staff to search customer accounts, sign in as a customer for troubleshooting (also in one click from the customer's Intercom profile), extend or restart trial periods, run legacy account migrations, and export a full copy of an organization's data for support and debugging
- `internal/sample-timesheet-seeding` **Sample timesheet seeding** — New accounts start with a single example time entry instead of a pre-filled week for several people
- `internal/sample-report-seeding` **Sample report seeding** — New accounts start with a set of example reports, in the sign-up language, to start from
- `internal/server-maintenance` **Automated server maintenance** — Weekly patch slots with a QA canary, pinned kernel, database, and runtime series, and self-healing reboots that roll back a failed boot on their own, so production servers stay patched without manual intervention
- `internal/request-entity-cache` **Per-request entity cache** — The server no longer repeats work when the same person, project or task shows up many times in one request, so pages and reports pulling large amounts of data load faster
- `internal/usage-metrics` **Usage metrics** — Scheduled jobs record per-organization product usage figures in Beebole's data warehouse for internal analysis
- `internal/server-logging` **Server logging & slow-request tracking** — Centralized server logs and tracking of heavy requests for operations troubleshooting; window titles and page text sent for activity classification are excluded from the logs
- `internal/worktree-switcher` **Worktree switcher** — Development-only sidebar control for switching between local git worktrees of the app; never shown in production builds
