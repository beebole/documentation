Tasks in Beebole are independent planning entities — units of work that you schedule, assign, and track time on. A task is not a sub-element of a project: tasks live on their own **Planning** page, and linking a task to a project is optional. Use tasks to plan the work to be done, and let your team track time directly on them.

<Info>
  To work with tasks, click **Planning** in the sidebar. The same tasks can be displayed in four views: the [Gantt chart](/help/documentation/gantt) for timelines, the [Kanban board](/help/documentation/kanban) for status columns, the [Staffing view](/help/documentation/staffing) for planning by person, and the [List view](/help/documentation/task-list) for working the list as a sortable table.
</Info>

## How tasks relate to projects

[Projects](/help/documentation/projects) describe what hours are logged _into_; tasks describe the work _to be done_. The two are connected but independent:

- A task can exist without any project. You can plan, assign, and complete it entirely on the **Planning** page.
- A task can be linked to projects through its **Projects** attribute in the task detail panel.
- Time can be tracked on tasks directly, in the **Tasks** section of the [timesheet](/help/documentation/timesheets).

For general work that isn't planned as a task, track time on projects and subprojects instead.

## Plannings

Every task belongs to a planning — a separate board with its own statuses, its own level names for the hierarchy, and its own mode: [tasks or bookings](#tasks-or-bookings). New Beebole accounts start with one planning named **Main plan**, with the statuses **Backlog**, **Queue**, **In progress**, and **Done**.

- **Switch plannings** — Click the planning name at the top of the **Planning** page and pick another one from the menu.
- **Create a planning** — In the same menu, type a name in the **Name of a new planning** field and click **Add**. The new planning opens in the mode you last picked, **Bookings** by default — see [Tasks or bookings](#tasks-or-bookings).
- **Open a planning's settings** — Click the settings button next to the planning name (its tooltip reads **Main plan settings** for the **Main plan** planning). The dialog holds the planning's mode and its [statuses](#task-statuses). The button only appears if you are allowed to manage tasks.

  <img src="/help/images/planning/planning-switch-menu.webp" alt="Beebole Planning page header with the planning name Main plan clicked, showing a menu with the Main plan and Staffing plan plannings, the Name of a new planning field and the Add button, next to the settings gear and the Add Task button" width="503" />
</Frame>

Statuses always belong to a planning, not to a project: each planning defines its own workflow. See [Statuses](#task-statuses) below.

## Tasks or bookings

Each planning in Beebole holds one kind of item. A **Tasks** planning is a list of things to do — a to-do list, issues, tickets — where every item has a name of its own and a status. A **Bookings** planning puts people on projects: each item is a person booked on a project over a date range, at an allocation. The choice belongs to the planning, not to the view: Gantt, Kanban, List, and Staffing stay available on every planning, so you can look at the same data either way.

To choose, open the planning's settings and pick a mode under **What this planning holds**:

<Frame caption="The Main plan settings: the planning's mode, then its task statuses">
  <img src="/help/images/planning/planning-settings-dialog.webp" alt="Beebole Main plan settings dialog with What this planning holds set to Tasks next to Bookings, each with its hint, the note on switching, and the Task statuses Backlog, Queue, In progress and Done with their Max tasks fields and the Add new status field" width="624" />
</Frame>

| Mode | What each item is | Hint shown in the dialog |
|------|-------------------|--------------------------|
| **Tasks** | A named item with a status | A to-do list, a to-do on a calendar, issues, tickets |
| **Bookings** | A person on a project, with dates and an allocation | Who is on what project, a vacant position, someone expected present |

A planning you add from the plannings menu opens in the mode you last picked under **What this planning holds**, whichever planning you picked it on. If you have never picked one, it opens in **Bookings**. Beebole remembers this last pick for each person separately. Existing plannings keep their mode: the **Main plan** of a new account, plannings created before this setting existed, and plannings created by an Asana, Linear, or Monday import are **Tasks** until you switch them. The mode decides what the add button opens and whether items carry a name of their own:

- In a Tasks planning, the add button reads **Add Task** and opens the name-and-status form described in [Creating a task](#creating-a-task). In a Bookings planning, it reads **Add Booking** and asks for the person (**Select the owner**) and the project (one of the two is enough), a date range, the planned time, and the allocation (**%**, **h/day**, or **Total**). The planned time is filled in from the person's work schedule, and you can change it. See [Adding a booking without dragging](/help/documentation/staffing#adding-a-booking-without-dragging) for the details of this form.
- A booking is named after its project and person, everywhere it appears, and cannot be renamed: clicking its name shows **A booking is named after its project and person**. Time is not recorded on a booking either: it goes on the project instead. In a Tasks planning, you name each task yourself.
- In the Gantt and List views, each **+** button on a row or a group header follows the mode. In a Tasks planning, a plain click opens a name field in place, and the new task gets the row as its parent or the group's owner, status, or project (see [Adding tasks in place](#adding-tasks-in-place)). In a Bookings planning, every **+** opens the **Add Booking** form with the row's task as parent, or with the group's person, project, or status, already filled in.
- On the Staffing timeline, a drag in a Bookings planning creates a booking on the spot. In a Tasks planning, it opens the add form with the dates and the person already filled in. See the [Staffing view](/help/documentation/staffing#creating-a-booking).

<Info>
  Switching keeps every name already stored: a booking shows its project and person instead, and its own name comes back if the planning returns to **Tasks**.
</Info>

## Creating a task

<Steps>
  <Step title="Open the Planning page">
    Click **Planning** in the sidebar, and check that the right planning is selected at the top of the page.
  </Step>
  <Step title="Click Add Task">
    Click the **Add Task** button. A form opens in the side panel.
  </Step>
  <Step title="Name the task and pick a status">
    Type the task name, and pick a status with the status selector below the name.
  </Step>
  <Step title="Submit">
    Click **Add new task** (or press **Enter**). The task appears in the active view, and you can fill in dates, owner, and other details from its panel.
  </Step>
</Steps>

<Frame caption="The add form: a name, the status selector, and the Or add multiple entries section below">
  <img src="/help/images/planning/add-task-panel.webp" alt="Beebole side panel for a new task with an empty Name field, the status selector on Backlog, the Cancel and Add new task buttons, and below them the Or add multiple entries section with a sample indented list and the Paste button" width="576" />
</Frame>

<Tip>
  Press **⌘\+A** (Ctrl\+A on Windows) anywhere on the **Planning** page to open the add form. If a task is currently open, the new task is created as its subtask.
</Tip>

A new task doesn't get a color of its own. It takes the color of its project, its owner, or its parent task, and shows that same color everywhere it appears — badges, dots, timesheet section headers, timers, and mentions. Pick a color on the task itself only when you want it to stand apart from the work it belongs to.

### Adding tasks in place

In the [Gantt](/help/documentation/gantt) and [List](/help/documentation/task-list) views, you can name new tasks right in the task list, without opening the add form:

- To add a subtask, hover over a task's row and click the **+** button next to its name. A name field opens under that row.
- To add a task to a group, hover over the group header of a grouped view and click its **+** button (**Add Task**). The name field opens at the top of the group, and the new task gets the group's owner, status, or project.

<Frame caption="The name field opened under a task's row in the Gantt, ready for a subtask's name">
  <img src="/help/images/planning/inline-name-field.webp" alt="Beebole Gantt task list of the Main plan with an empty Name field and its ✕ button opened under row 23, Fleet Dashboard, above Fleet Rollout, next to the start of the chart bars" width="828" />
</Frame>

Type the name and press **Enter**: the task is saved and an empty field opens for the next one. Leaving the field also saves what you typed, while **Esc** or the **✕** at the end of the field closes it without saving. No side panel opens: the new tasks appear in the view, ready to be opened for their dates, owner, and other details. A task added outside a status group gets the planning's first status.

To add several tasks at once, paste a list into the field: one name per line, with indented lines becoming subtasks of the line above, or a single line of names separated by semicolons. The field's tooltip says the same: **Paste a list: one per line or ;-separated**.

Hold **⌘** (Ctrl on Windows) when you click a **+** to open the full add form instead, with the same parent, owner, status, or project already filled in. The **+** buttons only appear if you are allowed to manage tasks, and in a Bookings planning they always open the **Add Booking** form, since a booking has no name to type.

### Adding many tasks at once

You can import a whole task list by pasting it from a spreadsheet — there is no file upload involved.

<Steps>
  <Step title="Open the add panel">
    Click **Add Task**. Below the form, find the **Or add multiple entries** section.
  </Step>
  <Step title="Copy and paste your list">
    Copy rows from a spreadsheet — one entry per line, using **Tab** or spaces to indent sub-levels — then click **Paste**. Indented lines become subtasks of the line above.
  </Step>
  <Step title="Review and confirm">
    Beebole shows the entries **Ready to import** as a tree. Remove any line you don't want, then click **Import entries**.
  </Step>
</Steps>

<Frame caption="A pasted task list in the Import preview, before Import entries">
  <img src="/help/images/planning/add-multiple-tasks.webp" alt="Beebole Add Task panel of the Main plan with the Backlog status selected and an Import preview below it: Launch Campaign with its subtasks Landing Page, Email Sequence and Paid Ads Setup, then Customer Onboarding Guide, each with a remove button, 5 Ready to import, and the Cancel and Import entries 5 buttons" width="576" />
</Frame>

Imported tasks get the status selected in the add form. After the import you can click **Undo** to remove everything you just added, or **New import** to paste another batch.

In a planning set to **Bookings**, the button reads **Add Booking** and opens the booking form instead of the name-and-status form — see [Tasks or bookings](#tasks-or-bookings).

## Task statuses

Statuses are the steps of a planning's workflow — the same statuses that form the columns of the [Kanban board](/help/documentation/kanban). To edit them, open the planning's settings dialog, which lists them under **Task statuses**:

- At the top of the **Planning** page, click the settings button next to the planning name.
- On the Kanban board, click a column's name.

In the modal you can:

- **Add a status** — Type its name in the **Add new status** field and confirm.
- **Rename or recolor a status** — Click a status to edit its name or pick a new color.
- **Reorder statuses** — Drag a status up or down. The order defines the column order on the Kanban board.
- **Limit a status** — Set **Max tasks** to cap how many tasks the status can hold. See [WIP limits](/help/documentation/kanban#wip-limits-are-hard-limits).
- **Delete a status** — Only possible when the status holds no tasks (including tasks marked done). Every planning must keep at least one status.

## Assigning tasks

Beebole distinguishes the person responsible for a task from the people it is available to:

- **Owner** — The single person doing the task. Pick them in the task detail panel (**Select the owner**); a task can only have one owner. Next to the owner you can set **% FTE**, the share of their working time dedicated to the task — Beebole uses the owner's [work schedule](/help/documentation/work-schedule) and this percentage when fitting planned time between the task's dates. Under the owner, **Tentative** marks the assignment as not confirmed yet: the task reserves the owner's capacity but stays out of reports until you switch it off, as for [tentative bookings](/help/documentation/staffing#tentative-bookings).
- **Potential owners** — People or [tags](/help/documentation/tags) the task is assigned to. In filters, these appear as **Potential owner** and **Potential owner tag**.

<Frame caption="A task's Owner panel: the owner, their share of working time, and Tentative">
  <img src="/help/images/planning/task-owner-panel.webp" alt="Beebole Owner panel of the QA Testing task: Sophie Laurent as owner, the % FTE field at 100%, and the Tentative switch turned off" width="538" />
</Frame>

Task managers are named in the **Managed by** section of the task panel, and managing a task covers its subtasks too. A person can also manage a whole planning, picked in the **Manages** section of their [profile](/help/documentation/people), and the managers of a [tag](/help/documentation/tags) manage the tasks tagged with it. Task managers can record time for others on the tasks they manage when their [role](/help/documentation/roles-authorisations) allows it, and they approve timesheets in approval stages of type **Task managers** (see [approver types](/help/documentation/approval#approver-types)).

<Info>
  Beebole can warn everyone involved before a task with no owner starts: the task manager and the assigned people are notified — the admins when the task has no manager. Configure the number of days in [Timesheet and Planning Settings](/help/documentation/timesheetSettings#reminders).
</Info>

## Subtasks and hierarchy

Tasks nest into subtasks, as deep as your plan requires. The hierarchy is shared by all views.

- To create a subtask, hover over the task's row in the Gantt or List view and click the **\+** button next to its name (see [Adding tasks in place](#adding-tasks-in-place)), or select the task and press **⌘\+A** to open the add form for a subtask.
- To indent or outdent with the keyboard, select a task in the Gantt or List view and press **Tab** to make it a subtask of the task above it, or **Shift\+Tab** to move it up one level.
- To move a task under a different parent, hover over the breadcrumb above the task's name (in the detail panel or on a Kanban card), click the edit button (**Change parent**), and pick the new parent with **Choose a task**. The list only offers tasks from the same planning.
- To expand or collapse a parent task, click the chevron next to it. **⌘\+Click** the chevron to expand or collapse all.

A parent task rolls up its children: it shows the period spanned by its subtasks and their total **Planned in hours**, read-only.

## Scheduling dates and planned time

Open a task's detail panel to set its schedule:

- **Dates** — Pick the start and end dates with the date-range picker. A task runs over whole days by default; uncheck **All day** to give it exact start and end times instead — see [giving a task hours](/help/documentation/gantt#giving-a-task-hours).
- **Planned in hours** / **Planned in days** — Enter the planned amount of work. Next to the value, a pill shows the capacity the owner's schedule leaves between the task's dates; hover it to read the planned time against that capacity.
- **Date locks** — Lock buttons flank the date picker (**Lock start date** and **Lock end date**). One edge is locked at a time — the start by default. When planned time no longer fits between the dates, Beebole moves the _unlocked_ edge: with the end date locked, the start moves earlier; with the start locked, the end extends. When planned time overflows the period, the pill turns red and grows two arrows: the down arrow cuts the planned time to what the period holds (its tooltip names both figures, as in **Reduce 12h to 8h**), and the up arrow moves the unlocked edge out to fit the planned time (its tooltip names the new date, as in **Change end date to 12 Mar 2026**).

Below the planned time, check **Plan on non-working days** to make weekends and public holidays count as working days for the task. The task then keeps the dates you give it instead of moving to the next working day. The owner's absences stay non-working. A parent task has no such checkbox, since its dates come from its subtasks.

If the owner already has another task with planned time in the same period, the panel shows an **Overlapping tasks causing overload** warning so you can rebalance.

<Frame caption="A task's schedule: whole days between the lock buttons, planned time with its capacity pill, and the overload warning">
  <img src="/help/images/planning/task-schedule-panel.webp" alt="Beebole Task details panel of QA Testing with the Oct 13 to Nov 29, 2026 date range between the Lock start date and Lock end date buttons, All day checked, Planned in hours set to 60 next to a 256h capacity pill, Plan on non-working days, the Queue status, and the Overlapping tasks causing overload list naming six other tasks" width="762" />

To sequence tasks — making one start after another ends — use [dependencies in the Gantt chart](/help/documentation/gantt#task-dependencies).

## Tracking time on tasks

Time entries can be recorded directly against tasks:

- **From the timesheet** — People add rows in the **Tasks** section of their [timesheet](/help/documentation/timesheets) and log hours on a task, just like on a project. Tasks someone owns are listed first in the add-task picker, so their own work is quickest to reach.
- **From a suggestion** — A dated task assigned to someone reaches them as a [suggested entry](/help/documentation/ai#suggested-time-entries) rather than being added to their timesheet as a row automatically. Accepting the suggestion creates the entry and pins the row. The exception is the **Allow only planned tasks in the timesheet** [restriction](/help/documentation/timesheetSettings#restrictions): when it is on, the tasks a person owns appear in their timesheet on their own, from every planning, and time can be entered only on those tasks and only within each task's planned dates.
- **From a Kanban card** — Hover over a card and click the clock button (**Add time**) to log time on that task for today. Once time is logged, the card shows a pill with the logged total next to the planned time, in hours (for example `4 / 8`). See [Kanban board](/help/documentation/kanban#tracking-time-from-a-card).

Which plannings accept time entries is controlled by the **Record time on these plannings** setting, in the **Categories** tab of [Timesheet and Planning Settings](/help/documentation/timesheetSettings). Tasks in other plannings don't show the time button.

You can also let task statuses drive time records with **Auto Timesheet from Planning**. Choose a **Start** and an **End** status per planning: moving a task into those statuses starts and ends its time records as [suggested entries](/help/documentation/ai#suggested-time-entries), which the person accepts in their timesheet. A status move never writes an entry into the timesheet directly. Set it up in the [Auto Timesheet from Planning tab](/help/documentation/timesheetSettings#auto-timesheet-from-planning).

<Info>
  From a person's or a project's action menu, **Go to tasks** jumps to the **Planning** page filtered on that person or project.
</Info>

## Descriptions, custom fields, and tags

Beyond scheduling, each task carries:

- **Description** — A rich-text panel for context, acceptance criteria, links, and file attachments, with @mentions to reference teammates. See [task descriptions](/help/documentation/kanban#task-descriptions) for the editor's features.
- **Custom fields** — Organization-defined fields (text, numbers, dates, URLs, booleans) that appear in the task detail panel. Define them in **Settings** \> **Custom Fields** and make them visible for tasks — visibility can even be limited to specific plannings. See [Custom fields](/help/documentation/custom-fields).
- **Tags** — Label tasks with [tags](/help/documentation/tags) to group and filter them across categories, and to report on them by team, client, or any dimension you define.

## Marking tasks done and deleting them

Each task has a **⋯** action menu (hover over its row in the Gantt or List view, or over its Kanban card) with **Duplicate**, **Rename**, **Done**, **Reopen**, and **Delete**.

<Frame caption="A task's ⋯ menu on its Kanban card">
  <img src="/help/images/kanban/card-menu.webp" alt="Beebole Kanban Queue column with the ⋯ menu of the QA Testing card open, listing Duplicate, Rename, Done, Reopen (unavailable) and Delete" width="350" />
</Frame>

**Done** takes a finished task out of the planning views. The task keeps its data and its time records, and the hours logged on it still count in reports. When a planning holds done tasks, the page header shows **Show Done** with their number: click it to bring them back into the views, and click **Hide Done** to hide them again. To restore a task, show the done tasks and click **Reopen** in its menu.

You can also mark tasks done from these places:

- The buttons at the end of each row in the [List view](/help/documentation/task-list#marking-tasks-done-from-a-row): **Done**, or **Reopen** on a task already done.
- A Kanban column's **⋯** menu, for every task in the column or only the selected cards (see [Kanban board](/help/documentation/kanban#board-layout)).
- **Set as done** in the menu of a task row in the [timesheet](/help/documentation/timesheets), for people allowed to manage tasks.

The task's history records each of these changes as **Done** or **Reopened**. When a submitted timesheet holds time on a task marked done, the [approval review](/help/documentation/ai#approval-review) flags it as **Time on a task marked done**.

<Info>
  **Done** is not a status. A task in a status named **Done**, such as the last column of the **Main plan**, stays in the views until you mark it **Done** from its menu, and marking a task **Done** leaves its status as it is.
</Info>

**Delete** removes the task permanently. A toast appears with an **Undo** button right after deletion.

<Warning>
  A task that has time records logged against it cannot be deleted. Beebole blocks the deletion and tells you whose time records are affected. Click the person's name in the notification to open their timesheet on one of those records; see [Delete protection](/help/documentation/concepts#delete-protection) for how this works across Beebole. Mark the task **Done** instead to keep historical data intact.
</Warning>

## Frequently asked questions

<AccordionGroup>
  <Accordion title="Are tasks part of projects in Beebole?">
    No. Tasks in Beebole are independent planning entities with their own page, statuses, and hierarchy. You can link a task to projects through its **Projects** attribute, but a task doesn't need a project to exist, be assigned, or have time tracked on it.
  </Accordion>

  <Accordion title="Can I import or export tasks in Beebole?">
    Import, yes — by pasting. Copy rows from a spreadsheet, click **Add Task**, find **Or add multiple entries**, click **Paste**, review the list, and click **Import entries**. Indent lines with Tab to create subtasks. There is no CSV file upload. Export, not from the Planning page: the Gantt, Kanban, List, and Staffing views are working views, so build the figures you need in [Reports](/help/documentation/reports) and [download them](/help/documentation/data-exports) as Excel, CSV, or PDF.
  </Accordion>

  <Accordion title="Can people track time on any task?">
    Only on tasks in the plannings selected under **Record time on these plannings** in Beebole's **Timesheet and Planning Settings**. Tasks in those plannings appear in the **Tasks** section of the timesheet and show the **Add time** button on their Kanban cards. Bookings are the exception: time is recorded on the booking's project, not on the booking itself.
  </Accordion>

  <Accordion title="What is the difference between a Tasks planning and a Bookings planning?">
    A Tasks planning holds named items with a status — a to-do list, issues, tickets — and its add button reads **Add Task**. A Bookings planning holds people booked on projects, each with a date range, planned time, and an allocation; its add button reads **Add Booking**, and every booking is named after its project and person. Choose the mode under **What this planning holds** in the planning's settings. A new Beebole planning opens in the mode you last picked, Bookings by default, while existing plannings keep theirs. All four views stay available in both modes, and switching keeps any stored names.
  </Accordion>

  <Accordion title="What is the difference between the Owner and the Potential owners of a task?">
    The **Owner** is the single person doing the task — Beebole uses the owner's work schedule and **% FTE** to fit planned time between the task's dates, and a task can only have one owner. **Potential owners** are the people or tags the task is assigned to; in filters they appear as **Potential owner** and **Potential owner tag**.
  </Accordion>
</AccordionGroup>
