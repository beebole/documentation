Beebole queries are the read operations of the [Beebole GraphQL API](/help/api/introduction). They return data from your account — your organization, people, projects, tasks, tags, time records, expenses, timesheet approvals, and custom fields — without modifying anything. Every query is sent as a `POST` request to `https://app.beebole.com/graphql` with your API key in the `apikey` HTTP header.

<Info>
  Queries never change data. To create, update, archive, or delete records, use [Mutations](/help/api/mutations) instead. For authentication setup, see the [API introduction](/help/api/introduction#authentication).
</Info>

Field names follow GraphQL conventions exactly as defined in the schema. Every entity exposes its identifier as `id` (not `_id`), and the organization-level query is spelled `currentOrganisation` (British spelling, as in the schema).

## Organization

Read account-level data with `currentOrganisation` and `getAuditTrails`.

| Query | Arguments | Returns |
| --- | --- | --- |
| `currentOrganisation` | none | The organization linked to the authenticated API key |
| `getAuditTrails` | `startTime`, `fromPersonId`, `affectedPersonId`, `operations`, `argumentMatch`, `responseMatch` | Audit trail entries for the organization |

```graphql
query {
  currentOrganisation {
    id
    name
    locked
  }
}
```

`getAuditTrails` returns the changes recorded in the account's [audit trail](/help/documentation/audit-trail). It works only for administrators, on plans that include the audit trail (not the **Free** plan). With no `startTime`, it covers the last seven days; a `startTime` returns the seven days that follow it. `fromPersonId` keeps the changes one person made, and `affectedPersonId` keeps the changes made to one person's time entries, whoever made them.

```graphql
query {
  getAuditTrails(operations: ["addTimeRecord", "deleteTimeRecords"]) {
    operationName
    timestamp
    person {
      id
      name
    }
    arguments {
      name
      value
    }
  }
}
```

## People

Read team members with `currentPerson`, `getPerson`, `getPersons`, `countPersons`, and `filterPersonIds`. `getPotentialProjectOwners` lists the people allowed to own a given project.

| Query | Arguments | Returns |
| --- | --- | --- |
| `currentPerson` | none | The person linked to the API key |
| `getPerson` | `id` | A single person |
| `getPersons` | `filter`, `archived` | A list of people |
| `countPersons` | `filter`, `archived` | The number of matching people |
| `filterPersonIds` | `filter`, `archived` | Only the IDs of matching people |
| `getPotentialProjectOwners` | `projectId` | People eligible to own the project |

```graphql
query {
  getPersons {
    id
    name
    email
    archived
  }
}
```

```graphql
query {
  getPerson(id: "64a1b2c3d4e5f6a7b8c9d0e1") {
    id
    name
    email
    role {
      id
      name
    }
  }
}
```

By default `getPersons` returns only active people. Pass `archived: true` to include archived ones.

```graphql
query {
  getPersons(archived: true) {
    id
    name
    archived
  }
}
```

## Projects

Read projects with `getProject`, `getProjects`, `countProjects`, and `filterProjectIds`. `getProjectCategories` lists the project categories projects are organized into, such as **Client** or **Internal**.

| Query | Arguments | Returns |
| --- | --- | --- |
| `getProject` | `id` | A single project |
| `getProjects` | `filter`, `archived`, `categoryId` | A list of projects |
| `countProjects` | `filter`, `archived`, `categoryId` | The number of matching projects |
| `filterProjectIds` | `filter`, `archived`, `categoryId` | Only the IDs of matching projects |
| `getProjectCategories` | none | All project categories |

```graphql
query {
  getProjects {
    id
    name
    level
    category {
      id
      name
    }
  }
}
```

The `level` field is the project's depth in the hierarchy, where `0` is a top-level project. Restrict results to one category with `categoryId`:

```graphql
query {
  getProjects(categoryId: "64a1b2c3d4e5f6a7b8c9d0e1") {
    id
    name
  }
}
```

```graphql
query {
  getProjectCategories {
    id
    name
    levelNames
  }
}
```

## Tasks

Read tasks with `getTask`, `getTasks`, `countTasks`, and `filterTaskIds`. `getTaskCategories` lists the task categories, which Beebole calls plannings.

| Query | Arguments | Returns |
| --- | --- | --- |
| `getTask` | `id` | A single task |
| `getTasks` | `filter`, `archived`, `startTime`, `endTime`, `categoryId` | A list of tasks |
| `countTasks` | `filter`, `archived`, `startTime`, `endTime`, `categoryId` | The number of matching tasks |
| `filterTaskIds` | `filter`, `archived`, `categoryId` | Only the IDs of matching tasks |
| `getTaskCategories` | none | All task categories |

On `getTasks` and `countTasks`, `startTime` keeps the tasks that start at or after a millisecond timestamp, and `endTime` the tasks that end at or before one.

```graphql
query {
  getTasks {
    id
    name
    startTime {
      ts
      iso
    }
    endTime {
      ts
      iso
    }
    status {
      id
      name
    }
  }
}
```

```graphql
query {
  getTask(id: "64a1b2c3d4e5f6a7b8c9d0e1") {
    id
    name
    effort
    dependencies {
      id
      name
    }
  }
}
```

## Time records

A time record is a logged time entry for one person on a specific day, linked to projects, a task, or an absence type. Read them with `getTimeRecord`, `getTimeRecords`, and `countTimeRecords`. `getAbsenceQuotaConsumed` returns how much of each of a person's time off allowances they have used.

| Query | Arguments | Returns |
| --- | --- | --- |
| `getTimeRecord` | `id` | A single time record |
| `getTimeRecords` | `startTime`, `endTime`, `time`, `absence`, `wfh`, `filter` | A list of time records |
| `countTimeRecords` | `startTime`, `endTime`, `time`, `absence`, `wfh`, `filter` | The number of matching time records |
| `getAbsenceQuotaConsumed` | `personId`, `absenceQuotaIds` | Time off consumed per allowance, in each allowance's unit (days or hours) |

`getTimeRecords` and `countTimeRecords` accept top-level arguments alongside `filter`:

- `startTime` / `endTime`: Unix timestamps in milliseconds bounding the period. A record is returned when it starts at or after `startTime` and ends at or before `endTime`.
- `time`: when `true`, return only worked time (entries without an absence type).
- `absence`: when `true`, return only absence entries (entries with an absence type).
- `wfh`: when `true`, return only entries logged as working from home.
- `filter`: a typed filter array (see [Filtering results](#filtering-results)).

```graphql
query {
  getTimeRecords(startTime: 1704067200000, endTime: 1706745600000, time: true) {
    id
    duration
    startTime {
      ts
      iso
    }
    nonBillable
    person {
      id
      name
    }
    projects {
      id
      name
    }
  }
}
```

`duration` is a number of milliseconds. `startTime` and `endTime` are `BeeboleTime` objects: select their subfields `ts` (a Unix timestamp in milliseconds) and `iso` (an ISO 8601 string). The `person`, `projects`, `task`, and `absence` fields resolve the related entities inline.

`getAbsenceQuotaConsumed` takes the IDs of the person's allowances, which you read from the person's `absenceQuotas` attribute (it includes allowances inherited from tags and the organization):

```graphql
query {
  getPerson(id: "64a1b2c3d4e5f6a7b8c9d0e1") {
    absenceQuotas {
      value {
        id
        startTime {
          iso
        }
        endTime {
          iso
        }
        absenceType {
          id
          name
          unit
        }
      }
    }
  }
}
```

Then pass the allowance IDs you want to measure:

```graphql
query {
  getAbsenceQuotaConsumed(
    personId: "64a1b2c3d4e5f6a7b8c9d0e1"
    absenceQuotaIds: ["64a1b2c3d4e5f6a7b8c9d0e4", "64a1b2c3d4e5f6a7b8c9d0e5"]
  )
}
```

It returns one number per ID, in the order you sent them, in the unit of each allowance's absence type. The count follows the carry-forward rules: a day taken while a carried-over balance is still valid is charged to that balance and never counted twice. An ID that is not one of the person's allowances returns `0`.

## Timesheets and approvals

A timesheet is one person's time records over one timesheet period, and its approval status — draft, submitted, approved, or rejected — belongs to the period, not to the individual records. Time records carry no status field, and `getTimeRecords` ignores the `status` input that the schema lists on its filter type. Read approval data with these queries instead:

| Query | Arguments | Returns |
| --- | --- | --- |
| `getApprovalState` | `personId`, `startTime`, `endTime` | The current status of one person's period, with its stage breakdown |
| `getPendingApprovals` | `showAll` | Submitted timesheets waiting for the key's owner — or every pending submission they may see, with `showAll: true` |
| `getTeamApprovalStates` | `personIds`, `startTime`, `endTime` | The status of several people's timesheets for one period |
| `getTimesheetTeam` | `startTime`, `endTime` | The people whose timesheets the key's owner may review for a period |
| `getApprovalEvents` | `personId`, `startTime`, `endTime` | Every approval event — submissions, approvals, rejections — on one person's period |
| `getPersonApprovalEvents` | `personId` | All of a person's approval events, in chronological order |
| `getApprovalEventById` | `id` | A single approval event |
| `getApprovalDigest` | `personId`, `startTime`, `endTime` | Rule-based anomalies in the period, for an approver to review before deciding |
| `getTimesheetScore` | `personId`, `periods` | The person's timesheet score over recent periods (12 by default) |
| `canApproveTimesheets` | none | Whether the key's owner may use the approval and team panes |

The `status` field on approval states and events uses one-letter codes: `d` (draft), `s` (submitted), `a` (approved), and `r` (rejected). An approval event can also carry `f`, which marks a period that auto-submit could not process: the period stays a draft.

### List timesheets awaiting approval

```graphql
query {
  getPendingApprovals(showAll: true) {
    person {
      id
      name
    }
    startTime {
      ts
      iso
    }
    endTime {
      ts
      iso
    }
    status
    currentStage
    totalDuration
    submitId
  }
}
```

### Check whether a period is still a draft

```graphql
query {
  getApprovalState(
    personId: "64a1b2c3d4e5f6a7b8c9d0e1"
    startTime: 1717200000000
    endTime: 1719791999999
  ) {
    status
    currentStage
    currentStageType
    submitId
  }
}
```

A period nobody has submitted yet returns `status: "d"`. To find every draft in a team, call `getTeamApprovalStates` with the team's `personIds` and keep the entries whose `status` is `d`. The `submitId` of a submitted period is what `approveTimesheet` and `rejectTimesheet` expect — see [Mutations](/help/api/mutations#timesheets-and-approvals).

## Expense records

An expense record is an expense logged by a person against a project and an expense type. Read them with `getExpenseRecord` and `getExpenseRecords`.

| Query | Arguments | Returns |
| --- | --- | --- |
| `getExpenseRecord` | `id` | A single expense record |
| `getExpenseRecords` | `startTime`, `endTime`, `filter` | A list of expense records |

```graphql
query {
  getExpenseRecords(startTime: 1704067200000, endTime: 1706745600000) {
    id
    date {
      ts
      iso
    }
    amount {
      value
      currency
    }
    comment
    expenseType {
      id
      name
    }
    project {
      id
      name
    }
  }
}
```

`date` is a `BeeboleTime` object (`ts` in milliseconds, `iso` as an ISO 8601 string). `amount` is an object with `value` (an integer in the currency's smallest unit) and `currency` (an ISO 4217 code).

## Absence types

Absence types are the kinds of leave people can log against, such as vacation or sick leave. Read them with `getAbsenceType`, `getAbsenceTypes`, and `countAbsenceTypes`.

| Query | Arguments | Returns |
| --- | --- | --- |
| `getAbsenceType` | `id` | A single absence type |
| `getAbsenceTypes` | `filter`, `archived` | A list of absence types |
| `countAbsenceTypes` | `filter`, `archived` | The number of matching absence types |

```graphql
query {
  getAbsenceTypes {
    id
    name
    unit
    involveCosts
  }
}
```

`unit` is `day` or `hour`.

## Custom fields

Custom field definitions and the values stored on records are separate entities. Read definitions with `getCustomField`, `getCustomFields`, and `countCustomFields`; read values with `getCustomFieldValue`, `getCustomFieldValues`, and `countCustomFieldValues`.

| Query | Arguments | Returns |
| --- | --- | --- |
| `getCustomField` | `id` | A single custom field definition |
| `getCustomFields` | `filter`, `archived` | All custom field definitions |
| `countCustomFields` | `filter` | The number of matching definitions |
| `getCustomFieldValue` | `id` | A single stored value |
| `getCustomFieldValues` | `filter` | Stored values, optionally filtered by field, entity type, or entity |
| `countCustomFieldValues` | `filter` | The number of matching values |

A value's `entityType` is one of `Person`, `Project`, `Task`, `Tag`, `TimeRecord`, or `AbsenceType`, and `entityId` is the record it sits on. The definition's `fieldType` is `text`, `number`, `date`, `datetime`, `url`, `boolean`, or `uniqueId`, and the value itself lives in the matching field: `textValue` (for `text` and `uniqueId`), `numberValue`, `dateValue`, `dateTimeValue`, `urlValue`, or `booleanValue`. The `person`, `project`, `task`, `tag`, `timeRecord`, and `absenceType` fields resolve the owning record inline — only the one matching `entityType` is set.

```graphql
query {
  getCustomFields {
    id
    name
    fieldType
    archived
  }
}
```

### Look up records by an external identifier

Beebole has no built-in external ID attribute: an identifier from another system lives in a text or [Unique ID](/help/documentation/custom-fields#unique-id-fields) custom field (a [migrated legacy account](/help/documentation/legacy-migration) gets a text field named **External ID**). To find the record that carries a given identifier, filter the field's values on `customFieldId` and `textValue`. The `textValue` filter matches the whole stored value, ignoring upper and lower case and any spaces around it:

```graphql
query {
  getCustomFieldValues(
    filter: [
      { customFieldId: "64a1b2c3d4e5f6a7b8c9d0e1", following: AND }
      { textValue: "EMP-0042" }
    ]
  ) {
    entityType
    entityId
    textValue
    person {
      id
      name
      email
    }
  }
}
```

The matching row's `entityId` is the Beebole record, and `person` resolves it inline when `entityType` is `Person` (use `project`, `task`, and the other entity fields for other types). On a Unique ID field, at most one record matches. To read the values on one known record instead, filter by `entityType` and `entityId`. Writing values is covered under [Custom fields](/help/api/mutations#custom-fields) on the Mutations page.

## Filtering results

The `filter` argument is a list of typed input objects, not a list of `field`/`value` pairs. Each entity has its own filter input type, such as `BeeboleTimeRecordFilter`, `BeebolePersonFilter`, or `BeeboleProjectFilter`. You set the named fields you want to match directly on each object.

```graphql
query {
  getTimeRecords(filter: [{ personId: "64a1b2c3d4e5f6a7b8c9d0e1" }]) {
    id
    duration
    startTime {
      ts
      iso
    }
  }
}
```

Each object in the array sets exactly one matching field: an object with two fields fails with `OnlyOnePropertyPerFilterAllowed`. To combine conditions, add a `following` value of `AND` or `OR` to chain one condition to the next, and leave `following` off the last object (an object without it anywhere else fails with `IncorrectFilter`). `AND` binds before `OR`, so `A AND B OR C` reads as `(A AND B) OR C`:

```graphql
query {
  getProjects(
    filter: [
      { categoryId: "64a1b2c3d4e5f6a7b8c9d0e1", following: AND }
      { archived: false }
    ]
  ) {
    id
    name
  }
}
```

### Time record filter fields

`BeeboleTimeRecordFilter` accepts these fields (each optional):

| Field | Type | Matches |
| --- | --- | --- |
| `id` / `notId` | ID | A specific time record, or all but one |
| `personId` / `notPersonId` | ID | Records for (or excluding) one person |
| `personIds` | `[ID]` | Records for any of several people |
| `startTime` / `endTime` | Timestamp | Records starting at or after / ending at or before a millisecond timestamp |
| `projectIds` / `notProjectIds` | `[ID]` | Records on (or excluding) projects, including their subprojects |
| `taskIds` / `notTaskIds` | `[ID]` | Records on (or excluding) tasks |
| `projectTagIds` / `projectNotTagIds` | `[ID]` | Records whose projects carry (or lack) given tags |
| `personTagIds` / `personNotTagIds` | `[ID]` | Records whose person carries (or lacks) given tags |
| `projectCategoryIds` / `notProjectCategoryIds` | `[ID]` | Records by project category |
| `taskCategoryIds` / `notTaskCategoryIds` | `[ID]` | Records by task category |
| `wfh` | Boolean | Records logged (or not) as working from home |
| `nonBillable` | Boolean | Records marked (or not) as non-billable |
| `following` | `AND` / `OR` | Logical operator chaining this condition to the next |

The schema also lists `isAbsence`, `status`, and `billable` on this input, but `getTimeRecords` and `countTimeRecords` don't filter on them: `status` and `billable` are ignored, and `isAbsence` matches no record. Separate worked time from absences with the top-level `time` and `absence` arguments, and read approval status with the queries under [Timesheets and approvals](#timesheets-and-approvals).

### Other filter types

Every other entity exposes a filter input tuned to its own fields. All fields are optional, `name` is a case-insensitive regular expression (so `Acme` also matches **Acme Corp**), and `following` chains conditions the same way.

| Filter input | Fields |
| --- | --- |
| `BeebolePersonFilter` | `id`, `notId`, `name`, `archived`, `roleId`, `tagIds`, `notTagIds`, `scheduleTypeId` |
| `BeeboleProjectFilter` | `id`, `notId`, `name`, `level`, `archived`, `categoryId`, `tagIds`, `notTagIds`, `assignedPersonId`, `managedById`, `subProjectId` |
| `BeeboleTaskFilter` | `id`, `notId`, `name`, `level`, `archived`, `categoryId`, `statusId`, `notStatusId`, `ownerId`, `ownerIds`, `notOwnerId`, `ownerTagId`, `notOwnerTagId`, `assignedPersonId`, `notAssignedPersonId`, `assignedTagId`, `notAssignedTagId`, `projectId`, `projectIds`, `notProjectId`, `assignedProjectId`, `childrenOfId`, `startsBefore`, `endsAfter`, `tagIds`, `notTagIds`, `taskTagIds`, `notTaskTagIds`, `personTagIds`, `notPersonTagIds`, `projectTagIds`, `notProjectTagIds`, `projectCategoryIds`, `notProjectCategoryIds`, `taskCategoryIds`, `notTaskCategoryIds` |
| `BeeboleTagFilter` | `id`, `notId`, `name`, `level`, `archived`, `categoryId`, `scheduleId`, `taggedPersonId`, `taggedProjectId`, `taggedTaskId` |
| `BeeboleExpenseRecordFilter` | `id`, `notId`, `personId`, `notPersonId`, `projectId`, `notProjectId`, `projectTagIds`, `projectNotTagIds`, `personTagIds`, `personNotTagIds` |
| `BeeboleAbsenceFilter` | `id`, `notId`, `name`, `archived` |
| `BeeboleCustomFieldFilter` | `id`, `name`, `archived` |
| `BeeboleCustomFieldValueFilter` | `id`, `customFieldId`, `entityType`, `entityId`, `notEntityId`, `textValue` |

For example, the projects that have a given person among their managers:

```graphql
query {
  getProjects(filter: [{ managedById: "64a1b2c3d4e5f6a7b8c9d0e1" }]) {
    id
    name
  }
}
```

Browse every filter type and its fields in the [Schema explorer](/help/api/schema-explorer).

## Counting and ID-only queries

For most entities (expense records are the exception), alongside the full `get…` query you also get a counterpart that returns just a count, and (for people, projects, tasks, and tags) one that returns only matching IDs.

- The `count…` queries (`countPersons`, `countProjects`, `countTasks`, `countTags`, `countTimeRecords`, `countAbsenceTypes`, `countCustomFields`, `countCustomFieldValues`) return an integer. Use them to size a result set before fetching it.
- The `filter…Ids` queries (`filterPersonIds`, `filterProjectIds`, `filterTaskIds`, `filterTagIds`) return an array of IDs instead of full objects, which is lighter when you only need identifiers.

```graphql
query {
  countTimeRecords(startTime: 1704067200000, endTime: 1706745600000)
}
```

<Info>
  The Beebole query API has no pagination — there are no `limit`, `offset`, `first`, or `cursor` arguments. A list query returns every record that matches its arguments. Narrow large result sets with `filter`, the `startTime` / `endTime` window, or `categoryId`, and use a `count…` query first to gauge the size.
</Info>
